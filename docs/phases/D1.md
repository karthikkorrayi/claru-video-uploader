# Phase D1 — Ready to deploy (no cost)

- Real Claru needs `ALLOW_REAL_CLARU=yes` in every environment (before, production mode skipped the check).
- Request ids: every response carries `X-Request-Id`; server errors show "reference abc123" to the user.
- One log line per request (method, full path without query, status, time, user); upload pieces at debug.
- Problems page (admin): server errors, failed background jobs, testers' browser errors; 30 days.
- Environment banner from `ENVIRONMENT_LABEL` ("Test server — mock Claru …").
- `deploy/`: bootstrap.sh (one-time server setup), release.sh (additive releases, health check,
  automatic rollback), push-release.sh (send HEAD from the Mac or CI), claru-logs, claru-admin,
  systemd units, Caddyfile (HTTPS), journald retention.
- `.github/workflows/ci.yml` (tests on every push) and `deploy.yml` (off until D4).
- `docs/DEPLOY.md`: D2–D5 step by step, logs, rollback, teardown.

Verified before delivery: shellcheck and actionlint clean; Caddyfile validated by Caddy; a real
release installed and went live; a deliberately broken release rolled back by itself; a 300 MB
upload over HTTPS through Caddy with Secure/HttpOnly/SameSite=Strict cookies.

Not verifiable before D2: bootstrap.sh on a real Droplet (systemd, apt, Let's Encrypt).
