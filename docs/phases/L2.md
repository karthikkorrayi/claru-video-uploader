# Phase L2 — Resumable upload

What it adds:

- **Upload page** (Uppy + tus). Pick or drop MP4 files and press Upload. Files go in 50 MB pieces; two files at a time.
- **Each file is declared first** (`POST /api/recordings`: name, size, fingerprint). The fingerprint is SHA-256 over
  the size plus the first and last 4 MiB, computed in the browser. The server answers with a recording id, and
  that id is also the upload's address (`/api/uploads/<id>`).
- **Resuming.** Wi-Fi drop or server restart: the browser keeps retrying for about 10 minutes, and retries again
  as soon as the network comes back. Tab or laptop closed: add the same file again and press Upload; the
  server says how much it already has and only the rest is sent. Works from another browser too.
- **On arrival** the server recomputes the fingerprint from the received file; a mismatch marks the upload failed
  and deletes it. Good files are moved to `WORK_DIR/<id>/original.mp4`.
- **No double uploads.** The same file again: resumes for the same person while in transit; refused for others;
  refused for everyone once received.
- **Disk guard.** A new upload needs free space of 2 × its size + all uploads in flight + `DISK_RESERVE_GB`.
  Otherwise the server answers "short of space" (HTTP 507) before any bytes move.
- **Recordings page.** Consultants see their own, the admin sees all (`ownerScope`, enforced in SQL). Shows
  progress, status, speed (MB/s and Mbit/s) and the average speed. Cancel (in transit) and Delete (received).
- **Only the uploader can send bytes** for a recording — not other consultants, not the admin. Checked in
  Express before the tus library sees the request. The CSRF header is required on every upload request.
- **Housekeeping** every 5 minutes: uploads with no data for `UPLOAD_ABANDON_HOURS` (72) are given up and their
  partial files deleted; an upload whose last byte arrived while the server stopped is completed.
- Audit log: recording_created, upload_received, upload_failed, upload_cancelled, upload_abandoned, recording_removed.

Settings (.env): `MAX_UPLOAD_GB` (8), `DISK_RESERVE_GB` (10), `UPLOAD_ABANDON_HOURS` (72).

Gate:

- `npm run check` passes (tests include a server restart mid-upload, a corrupted file, and every
  "someone else's upload" case).
- In the browser, with a real 2–4 GB recording (DevTools → Network throttling to slow it down):
  - Offline for 20 s, then back: continues by itself.
  - Restart only the API server (`touch server/src/index.ts` in a second terminal): continues by itself.
  - Ctrl+C on the whole `npm run dev`, start it again: Vite reloads the page (development only), the
    Upload page shows "Unfinished uploads"; add the same file → continues from where it stopped.
  - Close the tab, open a new one, add the same file: continues from where it stopped.
  Each must finish, once, as `Received`, and the file under `WORK_DIR` must be the same size as yours.
